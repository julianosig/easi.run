# Translations

The admin page and the site speak English and ten other languages (pt-BR, es, zh-CN, hi, fr, de, ja, ru, id, ko). Only
English is ever written by hand; the others follow it. Each package (client/, site/) has its own messages under
`messages/`, and both share the languages, the message format and the pipeline in `i18n/`.

## Writing English

- Every text a person can see or hear is a message in `client/messages/en/<area>.json`: visible text, `aria-label`,
  `title`, `placeholder`, `alt`, text given to a component (a heading, a help line), confirmations, and errors the
  page itself writes. Errors the server answers, protocol values, URLs, file names and code stay as they are.
- A key names what the message is for, inside its area, never its wording: `delete.confirm`, `filter.running`,
  `empty.title`. The page calls it as `t('area.key')`, the area being the file's name. Rewording a message keeps its
  key (and is translated again); a message for a new purpose gets a new key.
- A whole sentence is one message, with named placeholders: `"saved": "Saved {when} · {size}"`, never a sentence
  glued from pieces, which other languages order differently. Text around a link or an emphasis is split only where
  the markup is, each piece a message.
- A text that depends on a number is a plural message, an object of CLDR categories with `other` always:
  `"locked": { "one": "1 saved session is locked", "other": "{count} saved sessions are locked" }`; it takes `count`.
- Translations are text, never markup: no `{@html}`.
- A `.ts` module keeps keys, not text: a map of labels stores keys and the page translates them as it draws, so a
  language switch changes them at once. A module the unit tests import never imports `src/i18n/index.svelte.ts`; it
  returns keys, or takes the translating function as a parameter.

## The pipeline

```sh
cd client                         # or site/: each package has its own messages and runs the same pipeline
node ../i18n/sync.mjs --types     # the message types, from English, while writing (no network)
node ../i18n/sync.mjs             # translates what is new or changed, removes what is gone (ANTHROPIC_API_KEY)
node ../i18n/sync.mjs --check     # what the build checks: every language current, no network
```

Each translation keeps, in `client/messages/.sources/<locale>.json`, the hash of the English it was made from. A sync
asks Claude (`claude-haiku-5-5`), told what the package is by its `messages/brief.txt`, only for the messages a
language lacks or whose English changed, checks every answer (the same placeholders, as many times each, the plural
forms the language has), and removes from every language exactly the messages English no longer has. The committed
files are the only state; nothing is cached. `npm run check` runs `--check`, so a change to English without its
translations fails the build.

## The site

Each language has its own address for each page, rendered at the build with its words in the HTML: `/` in English,
`/<locale>/` for the others, and each later page below it, `/features/` and `/pt-BR/features/`
(`site/scripts/prerender.mjs`), each naming all of its languages for search engines (`hreflang`, canonical,
`sitemap.xml`). The menu links to every language; a browser that prefers another one sees, on the English
page, a note in that language offering it, never a redirect. The comparison's verdicts stay in
`site/src/lib/content.ts`; what stands behind each is a message (`ours.<row>`, `rivals.<rival>.<row>`).

## The docs

The docs (`site/src/docs`, at docs.easi.run) keep their messages apart from the landing's, in `site/src/docs/messages`
with their own brief, and run the same pipeline from `site/`:

```sh
node ../i18n/sync.mjs --messages=src/docs/messages --types-out=src/docs/keys.ts
```

Their prose may hold a closed set of inline markup, `<code>`, `<strong>`, `<em>` and `<a href="…">` (`i18n/rich.ts`):
`Rich.svelte` draws a message as elements, never as HTML, and the pipeline refuses a translation that does not keep
the same code, links (each with its code), emphasis and placeholders, properly nested. Text in `<code>` stays as it
is, braces included. Each language's docs are at `/<locale>/`, their pages still `#/<page>`; a page links to another
as `#/<page>` and to the landing through its English address, which takes the reader's language.

## The admin page's runtime

`client/src/i18n`: `t(key, params)` (typed from English by the generated `keys.ts`), the language chosen on the
browser or the browser's own, English for a missing translation, each language loaded when first chosen, and
`setLocale` switching live. Dates and numbers take the page's language.
